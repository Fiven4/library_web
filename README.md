# Библиотека: клиент библиотечной системы (Flutter Web)

Практические работы 2 и 3. Каталог из пяти сущностей со списками, поиском, фильтрами, сортировкой, постраничным выводом, формами создания и изменения, валидацией и сохранением данных между перезагрузками страницы.

Данные хранятся в `localStorage` браузера (через `shared_preferences`) и восстанавливаются из начального набора только при первом запуске. Сервер подключается позже, в ПР4: для этого заменяются только репозитории.

![Форма книги: издательство, авторы и жанры](docs/screenshots-pr3/02-form-all-relations.png)

## ПР3. Формы, валидация и связанные сущности

### Сущности и связи

| Сущность | Связи |
|---|---|
| Book | многие ко многим с Author и Genre (множественный выбор), многие к одному с Publisher (выпадающий список) |
| Author | многие ко многим с Book |
| Genre | многие ко многим с Book |
| Publisher | один ко многим с Book |
| Reader | один к одному с LibraryCard (вложенная группа полей в форме читателя) |

Поля всех моделей совпадают с контрактом учебного API (раздел 4), у каждой есть `toJson` и `fromJson`, устойчивые к отсутствующим и `null`-значениям.

### Что реализовано

- **Полный CRUD для всех пяти сущностей:** список, карточка, создание, изменение, логическое и физическое удаление, восстановление.
- **Один экран формы на создание и изменение:** маршруты `/books/new` и `/books/:id/edit` открывают один и тот же виджет, различие только в наличии идентификатора. Описание полей задаётся списком (`TextSpec`, `DateSpec`, `DropdownSpec`, `MultiSpec`, `GroupSpec`), общий виджет `EntityFormView` выводит поля, проверяет форму и отправляет данные для всех сущностей.
- **Валидация:** обязательность, длина, диапазоны, формат ISBN, почты, телефона, номера билета и даты, положительность количеств, проверка по нескольким полям (доступных экземпляров не больше общего числа, срок билета позже даты выдачи). Ошибки выводятся под полем, при отправке пустой формы видны сразу все. Валидаторы вынесены в `lib/core/validators.dart`.
- **Уникальность:** ISBN книги (дефисы не важны), почта и номер билета читателя, названия жанров и издательств. Ошибка выводится в поле, где допущено нарушение, и пропадает при правке значения.
- **Защита от удаления:** издательство, жанр и автор, на которых ссылаются книги, удалить нельзя, сообщение содержит число связанных записей. При групповом удалении такие записи пропускаются, а в сообщении указывается, сколько не удалено.
- **Каскад:** после выбора издательства список авторов сужается до тех, кто уже выпускал книги в нём (есть переключатель «показать всех»).
- **Несохранённые изменения:** при попытке уйти с формы (кнопка, «назад» браузера) через `PopScope` показывается подтверждение.
- **Сохранение и версии формата:** ключи `books_v2`, `authors_v2` и так далее. Данные старого формата (`*_v1`) переносятся автоматически, нечитаемые данные заменяются начальным набором. В обоих случаях пользователю показывается сообщение, приложение не падает.
- **Списки всех сущностей** поддерживают поиск, фильтры, сортировку, пагинацию, показ удалённых и карточки на узком окне (из ПР2).
- **Выпадающие списки и множественный выбор** заполняются из репозиториев, а не константами: добавленный жанр сразу доступен в форме книги.

## ПР2. Каталог: списки, поиск, фильтры, пагинация

Все условия отбора записываются в адрес, поэтому ссылку на отфильтрованный список можно отправить коллеге:

```
/books?search=война&genreId=2&publisherId=1&yearFrom=1960&sort=year,desc&page=1&size=10
```

![Список книг с фильтрами и адресной строкой](docs/screenshots/30-window-filters.png)

- Слои `models`, `repositories`, `state`, `screens`, `widgets`; состояние на `provider`, виджеты не обращаются к репозиториям.
- Поиск с задержкой 400 мс, фильтры (жанр, издательство, диапазон года), сортировка по заголовкам, пагинация с размером 10, 25 или 50.
- Выбор строк, множественное удаление с подтверждением, логическое и физическое удаление, восстановление.
- Четыре состояния экрана: загрузка, успех, пустой результат, ошибка. Для проверки в заголовке списка есть меню имитации сбоя и замедления ответа.
- Адаптивность: меньше 600 px карточки и нижняя навигация, шире таблица и боковая полоса.
- Обобщённые `EntityListView<T, Q>`, `EntityTable<T>`, `EntityListNotifier<T, Q>` используются для всех сущностей.

### Параметры адреса списков

| Параметр | Значение | По умолчанию |
|---|---|---|
| `search` | строка поиска | пусто |
| `genreId`, `publisherId`, `authorId` | число | нет |
| `yearFrom`, `yearTo` | число | нет |
| `country`, `city`, `card` | фильтр авторов, издательств, читателей (`active` или `expired`) | нет |
| `sort` | поле и направление: `year,desc` | первое поле, по возрастанию |
| `page` | номер страницы | 1 |
| `size` | 10, 25 или 50 | 10 |
| `includeDeleted` | `true` | нет |

### Ошибка в `deleteMany` (ПР2)

В исходном методе проверка записывалась так: `!b[i].isDeleted`. Код не компилируется: у `Book` нет оператора `[]`, а переменная `i` объявляется этой же строкой и используется до получения значения. Нужна проверка `!b.isDeleted`. Теперь метод общий для всех сущностей (`LocalRepository.deleteMany`) и покрыт тестами.

## Структура

```
lib/
├── main.dart, app.dart        точка входа, провайдеры, тема
├── core/                      router, validators, breakpoints, debouncer, format
├── data/seed_data.dart        начальный набор данных
├── models/                    Book, Author, Genre, Publisher, Reader, LibraryCard, запросы
├── storage/                   JsonStore (версии формата), StorageNotices
├── repositories/              интерфейсы и LocalRepository<T, Q> с пятью реализациями
├── state/                     списки, карточки, форма, справочники
├── screens/                   списки, карточки, формы, каркас с навигацией
└── widgets/                   EntityTable, EntityListView, форма (form/), карточка, пагинация
test/                          модели, репозитории, хранилище, валидаторы, формы, экраны
```
