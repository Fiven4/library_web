# Библиотека: клиент библиотечной системы на Flutter Web

Практические работы 2, 3 и 4. Каталог из пяти сущностей со списками, поиском, фильтрами, сортировкой, пагинацией, универсальными формами создания и редактирования, валидацией, связями и подключением настоящего REST API через Dio (на оценку «5»).

Web-приложение на Flutter для управления каталогом библиотечной системы из пяти связанных сущностей: книги (`Book`), авторы (`Author`), жанры (`Genre`), издательства (`Publisher`) и читатели (`Reader`) с вложенными читательскими билетами (`LibraryCard`).

Все параметры отбора (поиск, фильтры, сортировка, пагинация) синхронизируются с адресной строкой браузера: ссылку на любое отфильтрованное состояние можно скопировать и открыть в новой вкладке. В ПР4 хранилище в памяти полностью заменено на настоящий REST API сервер через библиотеку `dio` с сохранением неизменности виджетов и форм.

Разработка и запуск выполнены в Android Studio (устройство «Chrome (web)»).

## ПР4. Подключение REST API (Dio)

В практической работе 4 локальное хранилище заменено на интеграцию с учебным сервером по REST API. Реализация полностью выполнена по требованиям на **максимальную оценку «5»**:

### 1. Архитектурная изоляция сетевого слоя
- **Виджеты и экраны не изменились:** Замена хранилища выполнена исключительно подменой репозиториев в `lib/app.dart` (`Api*Repository` вместо `Local*Repository`). Ни один виджет не знает о существовании `dio` или `DioException`.
- **Иерархия исключений предметной области (`lib/core/api_exceptions.dart`):**
  - `NetworkException` — сетевые сбои, таймауты, недоступность сервера с **подсказкой о проверке CORS** в консоли браузера.
  - `UnauthorizedException` (401) — истечение токена / отсутствие авторизации.
  - `ForbiddenException` (403) — недостаточно прав для выполнения операции.
  - `NotFoundException` (404) — запись не найдена на сервере.
  - `ConflictException` (409) — нарушение целостности данных (например, удаление сущности со связанными записями).
  - `ValidationException` (422) — ошибки валидации полей от сервера с маппингом в карту `errors`.
  - `ServerException` (5xx) — внутренние ошибки сервера.
- Все сетевые исключения наследуют `RepositoryException`, поэтому стандартные обработчики форм и экранов перехватывают их прозрачно.

### 2. Конфигурация и сборка
Адрес сервера не зашит константой, а задаётся через параметр сборки (`lib/core/config.dart`):
```dart
const apiBaseUrl = String.fromEnvironment(
  'API_BASE_URL',
  defaultValue: 'http://localhost:8080/api',
);
```
Запуск клиента с нужным адресом:
```bash
flutter run -d chrome --web-port=5555 --dart-define=API_BASE_URL=http://localhost:8080/api
```

### 3. Интерсепторы Dio и устойчивость к сбоям
- **Журналирование:** В режиме отладки выводятся метод, адрес запроса, статус ответа и ошибки (`[API] GET /books -> 200`).
- **Разбор ошибок:** Коды `4xx` перехватываются в `onResponse` благодаря `validateStatus: (status) => status != null && status < 500` и преобразуются в `DioExceptionType.badResponse` с готовым `ApiException`.
- **Автоматический повтор (Retry):** При временном сетевом сбое интерсептор выполняет **до 3 повторных попыток с нарастающей задержкой** (500 мс, 1000 мс, 2000 мс). Повтор строго ограничен идемпотентными операциями чтения (`GET`), создание записей повторно не вызывается.

### 4. Отмена устаревших запросов (`CancelToken`)
При быстром наборе текста в строке поиска предыдущий незавершённый сетевой запрос немедленно отменяется через `CancelToken`. Это исключает «гонку запросов» (race condition), когда запоздавший ответ на короткую подстроку перетирает актуальный результат.

### 5. Кэширование справочников
Справочники (`authors`, `genres`, `publishers`) кэшируются в памяти репозитория при вызове `findAll()`. Они запрашиваются с сервера один раз и не перезагружаются при каждом открытии формы. При создании, обновлении или удалении сущностей кэш автоматически инвалидируется.

### 6. Защита от повторной отправки
В `EntityFormView` кнопка отправки формы блокируется на время выполнения сетевого запроса (`_saving`), предотвращая дублирование записей при повторных кликах.

## Сущности и связи

В системе реализовано 5 основных моделей, полностью соответствующих контракту учебного REST API (`api/КОНТРАКТ-API.md`):

| Сущность | Тип связи | Описание связей в системе |
|---|---|---|
| **Book** (Книга) | N:M с `Author`<br>N:M с `Genre`<br>N:1 с `Publisher` | При создании отправляются `publisherId`, `authorIds`, `genreIds`. При чтении сервер отдаёт развёрнутые объекты `publisher`, `authors`, `genres`. Модель `Book.fromJson` прозрачно поддерживает обе формы. |
| **Author** (Автор) | M:N с `Book` | В детальной карточке автора выводится список всех его книг. Защита от удаления при наличии связанных книг. |
| **Genre** (Жанр) | M:N с `Book` | В детальной карточке отображаются относящиеся книги. Контроль уникальности наименования. |
| **Publisher** (Издательство) | 1:N с `Book` | Карточка издательства показывает каталог его книг. Защита от физического удаления с указанием числа блокирующих книг. |
| **Reader** (Читатель) | 1:1 с `LibraryCard` | Читательский билет оформлен вложенной группой полей (`GroupSpec`): номер билета, даты выдачи и окончания срока действия. |

## Что реализовано

- **Чистая многослойная архитектура:**
  - `models` — DTO-модели (`Book`, `Author`, `Genre`, `Publisher`, `Reader`, `LibraryCard`) и объекты запросов (`*Query`) с сериализацией `toJson`/`fromJson`, устойчивой к `null` и отсутствующим полям.
  - `repositories` — абстрактные интерфейсы, реализация `ApiRepository<T, Q>` поверх `Dio` и резервная реализация `LocalRepository<T, Q>`.
  - `state` — управление состоянием на `provider` (`ChangeNotifier`). Виджеты изолированы от репозиториев и работают через нотифаеры (`EntityListNotifier`, `EntityDetailNotifier`, `EntityFormNotifier`).
  - `screens` и `widgets` — переиспользуемые компоненты `EntityListView<T, Q>`, `EntityTable<T>`, карточки и общая форма `EntityFormView`.
- **Серверная фильтрация, сортировка и пагинация:**
  - Поиск, сортировка по колонкам и разбивка на страницы выполняются сервером. Клиент хранит только текущую страницу.
- **Универсальный декларативный движок форм:**
  - Маршруты `/<entity>/new` и `/<entity>/:id/edit` используют единый виджет формы.
  - Поля описываются спецификациями: `TextSpec`, `DateSpec`, `DropdownSpec`, `MultiSpec`, `GroupSpec`.
  - Серверные ошибки 422 выводятся прямо под полями формы.
- **Многоуровневая валидация:**
  - Клиентская и серверная валидация: ISBN, Email, телефон, номер билета, даты, диапазоны.
  - Перекрёстные проверки и контроль уникальности.
- **Ссылочная целостность и каскады:**
  - Защита от удаления: при наличии связанных книг сервер возвращает 409 с описанием конфликта.
- **Безопасность данных и `PopScope`:**
  - Отслеживание изменений формы. При попытке покинуть несохранённую форму отображается диалог подтверждения.
- **Тестирование и качество:**
  - Полный набор модульных тестов с подменённым `Dio` (`test/api_repository_test.dart`): парсинг развёрнутых моделей, ошибки 422, конфликты 409, недоступность сервера/CORS, кэширование, отмена запросов через `CancelToken`.
  - Всего в проекте **138 тестов**, все проверки успешно проходят.
  - Статический анализ `flutter analyze` без единого замечания.

### Параметры адреса (Query Parameters)

| Параметр | Описание | Пример значения | По умолчанию |

| `country` | Фильтр авторов по стране | `country=Россия` | не задан |
| `city` | Фильтр издательств по городу | `city=Москва` | не задан |
| `card` | Статус билета читателя (`active` или `expired`) | `card=active` | не задан |
| `sort` | Поле и направление сортировки | `sort=year,desc` | первое поле, по возрастанию |
| `page` | Номер страницы (1-based) | `page=2` | `1` |
| `size` | Размер страницы (10, 25 или 50) | `size=25` | `10` |
| `includeDeleted` | Показывать логически удалённые записи | `includeDeleted=true` | `false` |
